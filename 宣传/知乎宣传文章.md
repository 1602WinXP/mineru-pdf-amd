"A 卡不能跑 mineru？"
"没有 CUDA 就只能用极慢的 CPU，或者买又贵又折腾的云服务器？"

如果你是 AMD 显卡（RDNA 2/3/4 架构）用户，在接触目前最强的开源文档解析引擎 **MinerU** 时，大概率会遇到类似的起步挑战。官方团队目前主要聚焦于模型核心效果和解析能力的迭代，官方文档以主流的 NVIDIA/CUDA 平台为主，其他算力生态则通过 Discussions 板块鼓励社区共同建设。此前，社区已经涌现出非常有参考价值的适配探讨（如 healy-hub 针对 MinerU 2.x 的优秀分享）。但 MinerU 3.x 升级了底层依赖与加速套件，老教程在新架构下需要不少调整。

## 🛠️ 技术挑战：AMD 显卡在 WSL2 上的三大难关

为什么在 AMD 显卡上部署 MinerU 如此困难？因为我们不仅要面对 ROCm 生态的碎片化，还要在 Windows WSL2 的虚拟化环境下解决底层硬件交互的硬伤。

这次部署中，我们合力攻克了三个核心技术阻碍：

### 1. 虚拟化环境下的"断头路"：KFD 驱动与 PyTorch 崩溃
在原生 Linux 上，ROCm 依赖内核级驱动 KFD 进行硬件访问。但 WSL2 中并没有 KFD 驱动，而是通过微软和 AMD 共同提供的 `librocdxg`（DXCore）技术将显卡资源间接桥接给 ROCm。
然而，**PyTorch 2.12.0 起默认集成了 `rocprofiler`（性能分析器），这个工具在启动时会去查询 KFD 拓扑结构**。在 WSL2 中查不到，PyTorch 就会直接闪退。
**解决办法**：在 WSL2 环境下，我们将 PyTorch 严格锁定在 **2.11.0**。这个版本避开了强制的 `rocprofiler` 检测，可以让深度学习环境平稳启动。

### 2. amdsmi 报错：vLLM 的识别硬伤
vLLM 在运行视觉大模型（VLM）时，默认调用 `amdsmi` 库来检测当前是否属于 ROCm 平台。但在 WSL2 下，`amdsmi` 因为拿不到底层驱动接口会初始化报错，导致 vLLM 误判当前平台没有 GPU，直接抛出 `Device string must not be empty` 错误。
**解决办法**：我们对 vLLM 的 `platforms` 判定逻辑打了两个补丁，让它在 `amdsmi` 报错时回退到 `torch.version.hip` 进行二次检查。这使得 vLLM 在 WSL2 里的 GPU 识别畅通无阻。

### 3. MIOpen 冷启动：突如其来的"7 秒延迟"
AMD 的 MIOpen（类似 NVIDIA 的 cuDNN）有一个机制：遇到新尺寸的卷积计算时，会在后台进行内核搜索（冷启动），导致每次解析新排版的页面时出现 1-7 秒不等的卡顿。
**解决办法**：我们应用了来自 Discussion #3662 的补丁，在 MinerU 图像输入端将页面尺寸对齐到 32 像素，并对 batch 进行零填充（zero-padding）；同时，我们提供了一个 `cache_warmer.py`（缓存预热脚本），提前把常用尺寸搜索好存入磁盘缓存。预热后，OCR 和版面识别的冷启动时间从 1 秒多缩短至 **30 毫秒** 级别。

## 📊 成果验收：AMD 显卡的逆袭

环境搭好后，我们用 `example.pdf`（13 页的复杂文档）对本地 **AMD RX 9070 (16GB)** 和云端 **NVIDIA A10 (24GB)** 进行了对比测试。

- **VLM 大模型推理（提取表格与文字）**：
  A10 稍快，用时约 5 秒；RX 9070 紧随其后，用时约 6 秒。
- **Layout 版面与 OCR 阶段**：
  **RX 9070 爆发了**。凭借 640 GB/s 的高显存带宽，处理速度达到了 **61 it/s**，而 A10 只有 **36 it/s**。
- **总耗时**：
  两者完成解析的时间都在 **6-7 秒** 左右，输出的 Markdown 和公式质量完全一致。

这证明了：**只要环境和补丁打得对，AMD 显卡本地运行的效率完全不输云端的主流 NVIDIA 推理卡。**

## 🧭 读者的快速部署指南

想在本地把 AMD 显卡用起来，可以按照以下步骤切入：

1. **检查显卡兼容性**：需要 RDNA2/3/4 架构（RX 6000 / 7000 / 9000 系列桌面卡，显存 ≥ 8GB）。
2. **按教程部署**：克隆仓库，按 [MinerU 本地部署教程](https://github.com/buptanswer/mineru/blob/main/%E6%95%99%E7%A8%8B/MinerU%E6%9C%AC%E5%9C%B0%E9%83%A8%E7%BD%B2%E6%95%99%E7%A8%8B.md) 走完（含 WSL2、ROCm 库安装、vLLM 源码编译等）。
3. **日常使用**：部署好后，可以通过命令行、WebUI，或者用仓库自带的 `mineru_api_client.py` 像调用官网 API 一样在局域网内远程调用。
